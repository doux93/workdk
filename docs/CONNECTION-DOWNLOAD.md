# 连接配置下载诊断 · 1.4.2

原前端将 `/api/agent-setup` 的所有非成功响应统一显示成“请使用工作台所有者账号登录后下载配置”，因此 HTTP 404、配置缺失或服务错误也会误导为账号问题。

本次修改只增加失败诊断和正常登录入口。`getChatGPTUser()` 仍读取平台认证中间件提供的登录身份，所有者匹配、机器凭据及来源检查保持原有规则；诊断函数不能授予访问权限。不更改站点访问范围，不提供跳过登录的配置下载路径。

| 错误码 / 状态 | 含义 |
|---|---|
| `AUTH_REQUIRED` / 401 | 应用接口没有识别到登录会话 |
| `OWNER_MISMATCH` / 403 | 已识别登录身份，但与当前所有者配置不匹配 |
| `OWNER_REQUIRED` / 403 | 机器调用不能代替所有者登录下载配置 |
| `ORIGIN_MISMATCH` / 403 | 浏览器请求来源不匹配 |
| `OWNER_CONFIG_MISSING` / 503 | 服务端缺少所有者校验配置 |
| `SETUP_NOT_CONFIGURED` / 503 | 已识别所有者，但缺少生成连接配置所需的服务端值 |
| 404 | 当前访问地址未提供采集 API，常见于仅启动前端的本机部署 |

前端显示 HTTP 状态和服务端实际错误，不再把未知失败认定为账号不匹配。失败后提供正常的顶层登录链接，以及新窗口 GET 下载入口，让平台按通常登录流程处理。配置仍只在授权成功后以禁止缓存的 JSON 附件下载。

验证：23 项 Agent / 安装 / 失败分类测试、21 项界面测试、前端及托管构建。覆盖未登录、错误账号、机器调用、缺少服务配置及不同下载 HTTP 状态的错误展示。分类测试使用合成身份判定结果，不能替代平台正常登录后的真实所有者请求。

本次排查通过只读工具确认站点仍仅允许所有者访问、三个运行时配置项存在。云浏览器没有现成登录会话，尚未完成用户正常登录后的下载请求实测，也未确认用户报告对应的实际 HTTP 状态。因此不能据原提示判断用户账号不对。
