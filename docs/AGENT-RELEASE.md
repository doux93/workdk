# Agent 工作日志 1.4 验收

## 实现范围

- Codex / Claude Code Hooks → 本地 SQLite 队列 → 私有接收 API → 云端 D1 → 工作日志页面。
- 只采集允许项目，提取任务描述、最终回复与工具元数据，基础过滤常见凭据及 URL 参数。不会读取对话历史文件或工具产生的文件正文。
- 15 秒批量同步，服务器确认后再标记已同步。失败记录留队列，状态脚本可查看。
- 幂等写入，按发生时间排序，跨日会话在日期筛选时显示相应日期的摘要。
- 摘要修正单独存储；原始事件保留。日志可添加到已有待办模块，同一会话不会重复添加。
- 复用 Agent 最终回复；没有额外模型调用、真实人工工时推断或自动派发任务。
- WorkBuddy：MCP 工具入口，自动调用依赖 Agent 行为；尚无原生完成回调适配。

## 自动检查

`npm run check`：17 项原有数据测试、17 项 Agent 队列/API 测试、17 项 React 界面测试、两组数据量检查和 TypeScript / Vite 构建。

Agent 测试覆盖：未授权拒绝、批次原子校验、十次重复上传、乱序补传、时区和跨日摘要、列表/详情分页、修正摘要保留原事件、凭据过滤、项目路径边界、工具正文不上传、连续断网 100 次、SQLite 重启恢复、服务器保存但响应丢失后的重传、无效确认及独立 Hook 子进程落盘。

界面测试基于 jsdom，覆盖接入入口、服务失败、本轮结束待验证、来源依据、添加待办、修正摘要和筛选分页，不代替真实操作系统 / CLI 兼容性测试。

原有数据压测覆盖 1000 / 5000 / 10000 条记录。新增 Agent 压测在内存 SQLite 中构造 1000 / 5000 / 10000 个事件，分别形成 100 / 500 / 1000 个会话。五次列表读取的最大值约为 3.3 / 9.0 / 18.1 ms，预算 2000 ms。结果为本执行环境的 CPU / SQLite 指标，不代表云端网络延迟。

## 已知边界

上传进程需要运行。未触发回调、电脑突然关机或 Agent 崩溃可能留下“执行中”记录，不能据此认定实际工作仍在运行。无稳定事件编号的源回调可能产生重复进展事件；网络重传不会产生重复服务器事件。敏感信息过滤不是保密审查，项目允许列表需由用户选择。第一版采用所有者级机器凭据，尚无单设备吊销或多用户工作区。
