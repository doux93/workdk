# 测试与性能说明（1.3.0）

## 一次完成检查

```bash
npm ci
npm run check
```

`check` 顺序执行 17 项数据测试、12 项自动界面测试、数据量压测和 TypeScript/生产构建。任一检查失败时退出为非零状态。也可分别执行 `npm run test:data`、`npm run test:ui`、`npm run test:perf` 和 `npm run build`。

## 自动界面测试

使用 Vitest、React Testing Library、user-event 和 jsdom，在实际渲染的 React 界面上模拟填写、选择、保存、搜索、关闭和翻页。测试位于 `tests/ui/`。

覆盖：数字/选项/链接输入、旧自由文本保留、非法链接拦截、字段类型设置、材料链接安全展示、未保存草稿保护、搜索隔离、多窗口版本提示与载入、大列表分页、看板分批、日历分批以及全局搜索结果上限。

这些是 DOM 层的组件与集成测试。原生对话框、matchMedia 和滚动接口在测试环境中替身实现；测试不等同于真实浏览器的像素、布局、屏幕阅读器或帧率验收。真实浏览器另行验证了数字录入及单位显示、选项选择、旧模块增加链接字段，以及详情中的链接展示。

## 数据量压测

```bash
npm run test:perf
npm run test:perf -- --write
```

第二条命令会更新 `reports/performance-latest.json`。每个操作先预热，再执行 5 次，记录中位数与 P95；样本较少时 P95 取最大值。测试包含内容断言和宽松的回归预算，超预算会使命令失败。

最近一次记录：Linux、Node.js v24.22.1。以下为该环境中 5 次样本的 P95，单位为毫秒：

| 记录数 | JSON 大小（MiB） | 数据校验 | 备份序列化及恢复 | 末尾记录搜索 | 模块筛选 | 内存保存 |
| ------ | ---------------- | -------- | ---------------- | ------------ | -------- | -------- |
| 1,000  | 0.38             | 0.91     | 3.26             | 0.51         | 0.79     | 0.96     |
| 5,000  | 1.90             | 4.12     | 14.37            | 2.26         | 2.27     | 5.15     |
| 10,000 | 3.81             | 6.36     | 29.49            | 8.40         | 7.66     | 11.69    |

压测使用合成内容与内存存储适配器，测量 CPU 工作与序列化成本，不测磁盘、网络或浏览器 localStorage 配额，也不承诺所有设备上的相同速度。真实记录的正文长度不同，文件大小也会不同。

界面测试另外检查了 1,000 条列表只渲染当前页的 50 条、看板每列先显示 30 条、单日安排先显示 50 条，全局搜索最多返回 30 条记录。剩余内容仍可翻页、继续显示或通过关键词定位。

## 兼容与维护

`Module.fields` 和 `Entry.values` 的原有格式保留，新增可选的 `Module.fieldConfig`。旧备份无需预先迁移；英语模板的已知字段可按名称使用默认控件。未知的旧选项和不符合新格式的旧文本不会被静默清空；新修改按字段类型校验。

组件已按首页、模板中心、模块视图、编辑器、字段、搜索和共享界面拆分。主页面文件从约 3,000 行减少到约 1,200 行；样式仍使用共享主题变量。

当前没有跨设备数据库、无限存储或真实 Windows 的自动化验收。浏览器容量不足时仍需导出备份。新增页面功能后应执行 `npm run check`；视觉变更仍需真实浏览器检查。

## Agent 日志回归（1.4）

- `npm run test:agent`：SQLite 队列、事件适配、API 写入/去重/查询以及独立 Hook 进程测试。
- `npm run test:ui`：新增 Agent 页面 5 项测试，总计 17 项。
- `npm run test:perf`：在原有数据压测后执行 `scripts/benchmark-agent.mjs`。
- `npm run check`：统一运行全部 51 项测试、两组压测和构建。

详细结果与真实设备验证边界见 [AGENT-RELEASE.md](AGENT-RELEASE.md)。

## 云电脑多进程验收

`npm run test:integration` 启动独立采集器、SQLite 队列、HTTP 接收服务及 MCP 进程，检查安装配置合并、断网补传、幂等写入、鉴权及 MCP 协议。此检查已加入 `npm run check`。Hook 载荷为模拟数据，不能代替真实 Agent 会话验收。

下载包和云电脑实测范围见 [CLOUD-AGENT-QA.md](CLOUD-AGENT-QA.md)。真实 Codex CLI 在该云环境因主目录只读而未能启动；未将此项标记为通过。
