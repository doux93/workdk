# 独立设备授权与升级（1.5.0）

每份新配置包含独立的 `device` 和 256 位随机上传令牌。服务端只保存令牌的 SHA-256 哈希。持有设备令牌只能向 `/api/agent-events` 上传该设备的事件，不能读取工作日志、修改摘要、签发或停用设备。所有者登录身份与本机管理员凭据保留管理能力。

## 操作

- 新电脑：连接电脑 → 填写名称 → 下载连接配置 → 用 1.5.0 采集器安装。每台电脑和每个 Windows / WSL 环境单独生成。
- 停用：设备连接 → 停用设备 → 确认。保留历史记录和客户端待上传队列，其他设备继续工作。
- 重新连接：原设备 → 重新签发配置 → 确认。旧令牌立即失效，新配置保留原设备编号。在原电脑导入新配置并重启上传器，同设备项目列表和队列保留。
- 下载中断：签发可能已在服务端完成。刷新设备列表找到新连接，可重新签发或停用；不会在设备列表重新展示旧令牌。

## 从共享凭据升级

1. 备份本机配置与队列，确认旧上传队列及 outbox 已清空，再停止上传器。若含多次旧初始化留下的不同设备编号，先用旧上传器处理这些记录。
2. 云端执行新增的 `0001_device_credentials.sql` 迁移，再同步后端和前端源码；本机服务启动时自动创建新表。历史事件、摘要和设备编号不变。
3. 若旧电脑仍需补传，云端可短暂设置 `AGENT_ALLOW_LEGACY_INGEST=true` 并保留 `AGENT_INGEST_TOKEN`。**在此期间，旧共享令牌仍能上传任意设备，不能靠停用单台设备撤销共享令牌。** 完成迁移后必须关闭该开关并轮换旧令牌。
4. 连接电脑的设备列表会显示已上报的旧设备，选择原设备「升级连接配置」。安装 1.5.0 采集器，导入对应配置后重启。已有采集器拒绝被不同设备编号的新配置覆盖；请不要删除原配置或队列绕过此检查。
5. 本机版还须更换 `WORKDK_INGEST_TOKEN` 并重启 API / Vite，以撤销旧配置中复制过的管理员令牌。新的设备令牌无需随管理员令牌变化而更新。
6. 逐台验证上传、停用拒绝、重新签发及补传，并确认历史日志仍可读取。

## 平台凭据与验证边界

在线配置还有平台层的 `serviceToken`，用于通过私有站点入口。单设备停用只撤销应用层上传权限，不会撤销这一平台令牌。如整份配置泄露，应同时轮换平台令牌，并为仍需接入的设备重新签发配置。

新增授权表的迁移是增量操作。迁移尚未执行时设备签发/认证会失败，应完成迁移后重试；不要删除数据库解决。仓库已覆盖 HTTP、SQLite、迁移 SQL、队列和浏览器管理交互；真实托管环境的身份头、D1 绑定及平台令牌仍需部署后验收。WorkBuddy 目前仍使用 MCP，尚未接入原生完成回调。
